# Office show

This directory is what you do **after** prove.

It is not `docs/Office-prove/`. Prove asks “does the door throw?”
It is not `docs/Agentic-update/prompts/`. Repair changes code.
It is not the ten-minute table in `.cfo-v2/office/final-demo/SCENARIOS.md`. That table is a **cut list**. It is not how you drive the month.

This directory is the **show**: one golden instance, a lived September, a recording on the Harness Demo page, then chapters you cut into videos.

---

## The short answer

**Do not run the prove procedures as the demo.**

You can put every procedure on one Computer. You must not. Prove Wakes say “call `tools.get_company_policies`.” That sentence stays in `protocol.jsonl`. The Demo slider will play it. Judges will see a test harness, not an office.

**Do not stitch prove instances into one tape.** AP on `prove-ap` and AR on `prove-ar` never share Handles. The judged story is one invoice across pipes. That requires one desk.

**Time pressure:** paste `docs/Office-prove/prompts/01-PIVOT-TO-SHOW.md` into the same prove-operator chat. That brief is the good-enough bar plus this directory’s calendar. Do not wait for P6/P7 INTENDED. Do not record `prove-*`.

**Do this instead:**

1. Finish prove on *other* instances (`docs/Office-prove/`), or stop at the pivot bar (one granted read on live Pi).
2. Create a **new** instance named `golden-<date>-r1`.
3. Run **onboarding**, then a **lived September** on that desk only.
4. `POST /api/demo/record` (Tools → Demo → Record). That snapshot is `harness/demo/latest/`. It survives wipe. Keep the instance anyway. That desk is the goose.
5. Cut chapters from the recording. The ten-minute script is one cut, not the only cut. Portfolio videos are several cuts from the same tape.

If a tool throws on the golden desk, **abort**. Do not patch skills mid-show. Go back to prove/repair. New `golden-r2`. The tape must not contain a traceback and a hot-fix.

## What “impressive at scale” actually is

The World pack is already large: 110 AP invoices, 200 September bank lines, 17 inbox messages, 66 AR invoices, 3,153 GL lines. Pi does not need to match all 110 for the desk to look like a company.

The golden run processes:

- **Featured** identities (the three public storylines plus inbox traps, one pay-run, one aging+send, close BLOCKED, audit, story).
- **Texture** (enough extra bills and bank ticks that protocol is not six stub Handles).

It does not process every Catalog op. That was P7. It does not load every Skill on a forced Wake. That was P6.

Scale on camera is: fifteen (or sixteen) Bots, mosaic panes, Handles between them, a month of protocol, close still honest about `$12.40`.

## Done for this operation

1. Instance id `golden-…` is selected. Not `live`. Not `prove-…`. Not `protocol-proof`.
2. Onboarding chapter exists in protocol: books (and sources) discovered a preexisting company. August CLOSED. September open.
3. Featured storylines moved on Handles: Acme `INV-001`, Helios `TXN-2026-09-011`, Northstar `TXN-2026-09-015` still unexplained.
4. Inbox traps did not become payables.
5. A weekly pay-run Handle reached `ctl-pay`. Collect sent only after apply, if send exists.
6. Close is BLOCKED. Story numbers UNLOCKED. Audit did not load ground truth. Operator did not concur.
7. `harness/demo/latest/meta.json` exists. Copy it off-instance as well.
8. `cuts/` names seq ranges after the run. You have not invented seqs in advance.

Then you decide which cuts become videos. The raw tape is already the portfolio object.
