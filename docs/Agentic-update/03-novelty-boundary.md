# Novelty boundary

A later Cursor agent will specialize per pipe. It will learn patterns and make connections this corpus does not list. This file marks the fence.

If a later writer over-designs inside the fence, the office becomes a checklist with a language model on top. That is not the product.

---

## What must stay true (not novel)

These are law. A specialist does not get to invent a second version.

1. Python wins on amounts. The model chooses among Kernel candidates. It does not invent totals, combinations, fees, or residuals.
2. Skills never grant tools. Grants come from compiled constructors.
3. Fail closed. Missing evidence is not a guess.
4. Do not union two Grant sets in one turn. A Wake names one Profile.
5. A Bot is not a child. The Roster is not `pi-subagents`.
6. Accept is not complete. A peer Handle is not approval.
7. The human Operator is not a worker. Verifiers own concurrence.
8. Operational Bots never load ground truth or `get_audit_ground_truth`.
9. The planted $12.40 unexplained bank difference stays unexplained in the judged demo.
10. Grain Tests A–D decide whether something is a Bot.

Kernel hard holds stay Kernel: `must_hold`, `enforce_collection_decision`, `validate_proposal`, `compute_tie_out`, `evaluate_close_gates`.

---

## What a pipe specialist is for

Inside the law, the specialist exists because two Kernel-legal options can both be true, and the office still has to pick one next step.

Examples of work that is judgment, not arithmetic:

- This vendor’s invoice is messy in a way the exception types do not name. Hold, or investigate, or ask World for a missing field.
- This customer always pays three invoices net of a discount two days late. The remittance does not say so. Precedent may color a later similar deposit. It may not override a live named invoice.
- This bank line looks like a fee. There is no fee advice. Do not invent a fee. Do say what would count as evidence.
- This 31-day invoice is a good payer vs a strategic account vs a quiet dispute. Tone and next step are not the same. Kernel still blocks paid, dispute, cooldown, and dirty unapplied cash.
- This flux move has three Kernel contributors. The sentence that belongs in the board pack is a choice among those contributors, not a new number.

The specialist should be able to form habits about counterparties, document layouts, and recurring breaks, and to use those habits the next time the same object class appears. That is memory. It is not a second ledger.

## What this corpus will not freeze

Do not write, in a later Skill or BOT.md, a numbered procedure that claims to be the specialist.

Do not freeze:

- How the Bot notices a vendor habit.
- The schema of Memory beyond “only your object, never another Bot’s Memory.”
- Which two facts it is clever to connect, except the four pipe handoffs already named in process law.
- A mapping table from aging bucket to email tone, once Kernel eligibility is already computed.
- A mapping table from exception_type to English sentence, once Kernel already emitted the type.
- A new Bot for every clever idea.
- A context graph product we do not have.
- A “CFO agent” that unions Grants and runs the month.

Process law already named four handoffs, not a mesh:

1. AR identifies customer deposits. Cash checks the bank agrees.
2. AP identifies vendor payments. Cash checks the bank agrees.
3. Cash hands trusted cash to close.
4. AR and AP hand agings that tie to close.

A specialist may notice more connections than those four. This corpus does not enumerate them. Enumerating them would be the over-design.

## What a Skill is for, if it stays

Kernel README for skills:

> A skill should answer: “What specialized procedure or domain knowledge does this agent need to perform this recurring task well?”

That is the intended function of a Skill. The live files mostly answer: “Here is the Kernel policy again, as a checklist.”

A Skill that is worth keeping does one of these:

- Tells the model what kind of judgment this object needs, without scoring the judgment.
- Tells the model which Kernel fields are authoritative, so it does not re-sum.
- Tells the model what it must not do (dun before apply, invent a fee, load ground truth).
- Names the output type and the Verifier when the grain already named one.

A Skill that is not worth keeping as-is:

- Restates `must_hold` cases.
- Maps bucket → action as if the model owned eligibility.
- Claims the output is “preview only” when the office must actually send.
- Exists only because a constructor used to be long.

This file does not rewrite the skills. It states the inadequacy.

## What BOT.md is for, if it stays

BOT.md is standing identity: who you are, what you own, how you wake, what you must not do, when you are done.

Protocol belongs here: Handle, await, peer Handle is not approval, never `ask_user`.

Case law does not belong here as the specialist’s brain: INV-009-class, MSG-S12, a full match algorithm.

Memory belongs here as a boundary (your object only), not as a retrieval algorithm.

---

## Intended feature for novelty, still without a design

Each pipe Bot should, over a month of Maximor tickets:

- Get better at the same counterparty without a human editing `prior_cases.json`.
- Refuse a cousin of a break it has seen, for a reason it can write down.
- Hand the next pipe an identifier, not a second interpretation of the same bank line.
- Leave a trace a Verifier and an auditor can read.

How it notices, stores, and retrieves that is the later agent’s work. This corpus only requires that the capability exist, and that it not violate Kernel law.
